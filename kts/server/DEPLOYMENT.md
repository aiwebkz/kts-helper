Приватный ключ находится только на VPS в `data/id_ed25519`, права `600`;
каталог `data` имеет права `700`. Не заменяйте ключи при перезапуске: клиенты проверяют
подлинность сервера по встроенному публичному ключу.

Firewall разрешает только на `tailscale0` TCP 21115–21117 и UDP 21116. SSH и существующие
правила других приложений сохранены. Порты WebSocket 21118–21119 не открывались.
Оба компьютера должны войти в tailnet сервера, а его ACL — разрешать указанные порты.
По публичному IP сервер недоступен: VPS находится за NAT без доступного проброса портов.

Команды после входа по SSH:

```sh
cd ~/kts-helper
docker compose ps
docker compose logs --tail=100 hbbs hbbr
docker compose restart
```

Для повторного запуска из остановленного состояния:

```sh
cd ~/kts-helper
sh start.sh
```

Исходная конфигурация — `compose.yaml`, `.env` содержит `RELAY_HOST=100.90.108.74`.
Для резервной копии остановите **только этот** Compose-проект, сохраните `data` вместе с
ключами/БД и снова выполните `sh start.sh`. Архив с приватным ключом храните вне Git.

Нужно дополнительно проверить реальные клиентские сеансы Mac ↔ Windows в tailnet.
Проверка открытых сокетов и журналов сервера не подтверждает работу захвата экрана,
ввода, разрешений macOS или прохождение ACL между другими устройствами.
